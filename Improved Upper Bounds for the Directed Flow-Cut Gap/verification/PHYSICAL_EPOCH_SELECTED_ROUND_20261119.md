# Physical midpoint round from a selected epoch demand

`EpochGridLookupProgram.stored_epoch` exposes the list and grid table on the heap returned by `PhysicalEpochInputProgram.physical_epoch_input`. A 104-slot program compares both actual labels to find the selected pair’s stored grid word. It returns the stored word with its original padding, or the empty zero word if the label is absent.

`EpochSelectedRoundProgram.physical_round` uses that lookup in a fixed 2,451-slot table. The program computes the row-major address from the selected labels and the stored vertex count. It loads the actual current weights and trims their padding while building the target list and the rational cost table. It builds the midpoint cut context and the state update context on the same heap, including unary indices from the two original labels. It then passes these actual pointers to the physical midpoint cut and mask-and-mass update. `cut_of_epoch` identifies the cut with the exact integer controller’s midpoint cut.

The input representation contains the selected pair, the grid table, the canonical vertex list, the adjacency and current masks, the stored size and unit word, and the current weight table. The theorem preserves the source and heap prefix and includes a bound for successful instructions and the paid halt. Its width parameters count the actual stored words. The full epoch loop and candidate refresh remain separate obligations.

The executable fixture calls the existing guarded epoch program with literal fair bits. It takes its first pair pointer and grid table pointer from the returned heap. The selected-round program reads cell 1 for `(0, 2)`, removes that demand, returns cut `[true, true, false]` and current mass 5, and preserves the unread suffix. The epoch used seven fair bits and paid 18,713,705 modeled operations. The selected round used 11,483 successful instructions and paid 730,087,492 modeled operations including halt. Three additional cases cover colliding labels, stored padding, and absent keys.
