# Dependency artifact provenance plan — not executed

The artifact specification remains `UNAVAILABLE_REVIEW_REQUIRED`. No download, extractor, native build, Lake, Cache.Main, Lean, or checker is run by this plan. Preparation tests use synthetic inert bytes only. A missing dependency or native library must fail; it must never launch a build or hidden compiler fallback.

A reviewable artifact must arrive with all of the following, hash-bound in one provenance bundle:

1. **Source and toolchain identity.** Exact nine revisions from the unchanged manifest (SHA256 `615d78a994009475b0e34cd0cd67325b2d863ae37e9f42d8ded7f9d575bf4b2f`), including mathlib `5ed2965256430c3649e86755f9576b54eca72435`; official Lean `leanprover/lean4:v4.34.0`, revision `293d5d0c0c3f3dded4688b3ccd6a33939ac5102b`; official distribution SHA256 `caaa98356098c85dc0fcbbd28e1ec66f39eb6551829972b752ff20e1286b646b`.
2. **Pinned module-to-archive map.** For every required dependency module: package/revision, source path/SHA256, ordered import dependencies and their identity hashes, exact official cache key, and exact official archive URL. The producer must authenticate the link between that key and pinned sources, using a trusted official producer index or an independently reviewed non-Lean implementation of the exact pinned cache hash algorithm with authoritative comparison vectors. A source-file SHA256 alone is not an official cache key. This map is currently absent.
3. **Authenticated archive bytes.** Per archive: exact URL, byte length, SHA256, download/provenance evidence, official producer identity/attestation or explicit independently reviewed trust basis, and transport/redirect records. A SHA256 computed after downloading arbitrary bytes does not independently establish which source produced them. Do not confuse the official cache key with a cryptographic content hash. The pinned Cache.IO comments explicitly warn that changing ltar bytes need not change the key. No authenticated archive hashes are currently available here.
4. **Unmodified extractor identity.** Independently compare the extractor bytes against those from the SHA256-verified official distribution. `evidence/extractor-read-only.json` records the locally installed `leantar` hash and byte length, without executing it; that observation is not itself the missing distribution comparison. Future extraction uses an absolute verified executable, never `lean --print-prefix`. The pinned Cache.IO command is `leantar -x --delete-corrupted -j -`, with an exact separately hashed JSON-array stdin configuration. Record cwd, environment, stdin bytes/hash, command/options, UUID, PID, time, exit, stdout/stderr and reaping. No invocation occurs now.
5. **Archive-to-file mapping.** For every produced object: originating archive URL/hash/member, extraction destination, module identity, source SHA256, file length and SHA256. Extract only into an empty staging tree; inspect full membership before packaging. Reject paths/links escaping staging, project objects, unexpected outputs and conflicting destinations. Include all dependencies actually required for compilation, resolution and replay. If the existing consumer suffix allowlist is insufficient, stop for a reviewed contract change; no `.so`/native/build fallback is allowed.
6. **Complete bundle inventory and identity.** Package only reviewed dependency objects under their nine `.lake/packages/<pin>/.lake/build/lib/lean` roots plus the manifest. Retain ordered inventory, individual hashes, full artifact SHA256/length, immutable fetch URL, exact reproducible packaging command and reviewed provenance evidence commit. Record all source/toolchain/pin hashes in the manifest. The artifact must contain zero LightEFT or LightSpanners project objects.
7. **Independent reconciliation before enablement.** A reviewer checks module-map completeness, authenticated archive hashes, extractor provenance, extraction receipts, file mapping and bundle bytes. Only a separately reviewed code/spec checkpoint may replace the unavailable spec with exact reviewed artifact values. Current `install()` checks paths/hashes/pins but does not independently prove official provenance; that trust must not be inferred from a URL string.

The future clean gate then downloads and checks this artifact using Python only. It preserves the downloaded bytes and manifest and builds all 486 project modules freshly. It never runs the old cache initializer. No suitable authenticated artifact or complete mapping has been identified; this is an explicit artifact/provenance gap, not a request for Greg to debug the harness.
